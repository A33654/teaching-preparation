# 教师在线批改模块 PRD（AI 辅助 · 含误区回流）

> 模块定位：在现有「教师智能备课系统」上延伸教学闭环——备课产出教案/习题 → 一键生成作业 → AI 辅助批改 → 教师复核 → 按知识点聚合错误 → 回流补全知识图谱误区节点。
> 设计原则：**AI 批改是辅助确认，不是替代判分**；学生数据全程去标识化、最小必要。

## 一、需求分析

### 1.1 背景与问题
- 现有系统已能产出规范教案（含重难点、易错点、板书、课堂习题），但**止于教案即断片**，教学闭环缺失"练—批—反馈"环节。
- 教师手工批改主观题耗时高，且**错误规律未被结构化沉淀**；而系统中知识图谱恰好有`误区+纠正`字段，却没有从真实教学反哺的通道。
- 价值缺口：备课沉淀的图谱（知识点/前置链/难度/误区）与真实课堂脱节，形成"建了没人用、用了不回流"的死库。

### 1.2 目标
把"备课知识图谱"升级为**课程语义中台**的第一块拼图：让批改结果反哺图谱，形成 `备课 → 作业 → 批改 → 误区回流 → 图谱更准` 的正循环。

### 1.3 成功指标与口径

| 指标 | 目标值 | 口径与公式 | 排除项 |
|------|--------|------------|--------|
| 客观题自动判分准确率 | ≥ 95% | 标注集上自动判分正确题数 ÷ 总题数 | 不计主观题 |
| 教师主观题复核效率提升 | ≥ 50%（估算） | （纯人工单份耗时 − 使用本模块单份耗时）÷ 纯人工耗时 | 仅统计采纳 AI 建议的 Submission |
| 误区回流教师采纳率 | ≥ 30%（估算，监控项） | 教师确认补入图谱的误区建议数 ÷ 系统推送的误区建议数 | 教师主动忽略的不计 |
| 知识点错误率看板覆盖率 | 100% | 已发布作业中关联知识点均出现在看板的比例 | — |

> 标注：带"估算"的目标为经验假设，需首轮试点（≥1 个班级、≥3 次作业）后回测校准。

### 1.4 用户角色

| 角色 | 描述 | 主要场景 |
|------|------|----------|
| 任课教师 | 创建/发布作业、复核 AI 批改、确认误区回流 | 从教案生成作业 → 复核 → 看板 → 补图谱 |
| 教研管理员（超管） | 查看校本错误基线、审核图谱变更 | 全校知识点误区质量闸门 |
| 学生（数据主体） | 提交答案 | **本期仅模拟提交/教师代录，不建独立学生端** |

### 1.5 范围

- **本期包含**：作业生成（复用教案习题）、题型支持、AI 客观题自动判、AI 主观题辅助建议、教师复核终评、错误聚合看板、误区回流建议与确认、脱敏导出。
- **本期不包含**：
  - 独立学生端 App / 移动提交（以"模拟提交/教师代录"替代，记为后续版本）；
  - 学生行为画像、阅读速度/兴趣分析（未成年人合规红线，不碰）；
  - 自研直播/视频互动（仅取轻量信号，不建传输，见后续版本）。

### 1.6 约束
- 合规：学生提交数据必须去标识化（学号哈希/昵称），最小必要存储，不用于商业推送。
- 技术：复用现有 `lesson_plan_graph`（产课堂习题）、知识图谱 Repository、现有 LLM 流水线；不引入新模型栈。
- 可信：AI 主观题**不得直接定终评**，必须教师确认。

## 二、方案概述（与现有系统的咬合点）

```
教案(课堂习题) ──FR-01一键生成──> 作业 Assignment
        │                                  │
        └── 关联知识点(图谱) <─────────────┘
作业 ──FR-03模拟提交──> Submission
        │
        ├─ 客观题 ──FR-04 自动判分
        └─ 主观题 ──FR-05 AI建议分+评语+知识点命中+置信度
                                │
                FR-06 教师复核(采纳/改分/终评)
                                │
                FR-07 按知识点聚合错误率
                                │
                FR-08 高频错误→误区回流建议→教师确认→写图谱误区节点
```

**复用点**：作业题目强制关联图谱`知识点`；错误聚合的"知识点"维度直接来自图谱；回流写入复用现有`误区+纠正`字段与审核链路。

## 三、功能需求

### 3.1 作业管理

| 编号 | 需求描述 | 业务规则 | 验收标准 |
|------|----------|----------|----------|
| FR-01 | 从教案一键生成作业 | 取该教案`课堂习题`为初始题目；题目自动继承教案关联的知识点；教师可增删改 | Given 教师打开某份已生成教案，When 点击"生成作业"，Then 进入作业编辑页且题目与知识点预填，可编辑 |
| FR-02 | 作业编辑与题型支持 | 支持选择/填空/简答/论述四类；每题必选≥1 个关联知识点；填空答案支持多解 | Given 编辑作业，When 新增一道简答题并选择知识点K，Then 该题保存且关联K，提交时未关联知识点的题被拦截 |
| FR-03 | 发布与（模拟）提交 | 发布后生成提交入口；本期学生提交以"模拟提交/教师代录"实现，不依赖学生端 | Given 作业已发布，When 教师用"模拟提交"录入一份答案，Then 生成 Submission 且状态=已提交，学号以哈希存储 |

### 3.2 AI 辅助批改（核心边界）

| 编号 | 需求描述 | 业务规则 | 验收标准 |
|------|----------|----------|----------|
| FR-04 | 客观题自动判分 | 选择/填空由规则+标准答案自动判；输出得分与解析；准确率验收≥95% | Given 一份含 10 道选择题的 Submission，When 触发自动判分，Then 标准答案题判分正确率≥95%（标注集），错判题可溯源 |
| FR-05 | 主观题 AI 辅助建议 | AI 输出：建议分、批改评语、命中知识点、置信度(0-1)；**不写终评**；置信度<0.7 强制标记"建议人工" | Given 一道简答题，When AI 批改完成，Then 显示建议分+评语+置信度，终评字段为空且系统提示需教师确认 |
| FR-06 | 教师复核与终评 | 教师可对每题"一键采纳建议"或"手动改分+写评语"；提交终评为不可逆操作需二次确认 | Given AI 已给建议，When 教师点击采纳或修改后确认，Then 终评落库且界面提示"已确认不可改"，改分需二次确认弹窗 |

### 3.3 反馈与回流

| 编号 | 需求描述 | 业务规则 | 验收标准 |
|------|----------|----------|----------|
| FR-07 | 错误聚合看板 | 按关联知识点统计错误率、高频错误模式；支持个人/班级视角；覆盖全部关联知识点 | Given 一份作业全部批改完成，When 打开看板，Then 每个关联知识点均有错误率与 TOP 错误模式，无遗漏 |
| FR-08 | 误区回流建议与确认 | 对错误率≥阈值(默认40%，可配)的知识点，推送"建议补入图谱误区"卡片，附典型错误表述；教师确认后写入该知识点`误区+纠正` | Given 知识点K错误率45%，When 教师确认回流建议，Then K 的误区节点新增一条经审核的记录，且来源标注"教学回流" |
| FR-09 | 脱敏导出 | 支持按班级导出成绩/批改明细（Excel/PDF）；学号以哈希/昵称呈现，不含明文身份 | Given 导出作业成绩，When 生成文件，Then 文件中无明文学生姓名/学号，仅哈希标识 |

### 3.4 权限与隔离

| 编号 | 需求描述 | 业务规则 | 验收标准 |
|------|----------|----------|----------|
| FR-10 | 数据隔离 | 教师仅可见本人/本人班级作业与 Submission；超管可见全校聚合但不看个人明文 | Given 教师A登录，When 访问作业列表，Then 仅显示A发布的作业，越权访问返回空或拒绝 |

## 四、业务流程与状态流转

**Assignment 状态机**：草稿 → 已发布 → 收集中 → 已截止 → 已批改完成
- 草稿→已发布：教师发布
- 已发布→收集中：开放提交
- 收集中→已截止：到达截止时间或教师手动截止
- 已截止→已批改完成：全部 Submission 终评确认

**Submission 状态机**：未提交 → 已提交 → AI 批改中 → 待教师复核 → 已确认
- AI 批改中→待教师复核：客观题判完 + 主观题建议生成
- 待教师复核→已确认：教师终评确认（不可逆）

**GradingItem（单题）状态**：待 AI → AI 建议(客观已定/主观建议) → 教师已确认 / 教师已改

## 五、数据设计

### 5.1 新增实体（建议模型）
- `Assignment`：id, lesson_plan_id(可空), title, status, deadline, created_by
- `AssignmentQuestion`：id, assignment_id, type(选择/填空/简答/论述), content, std_answer, knowledge_point_id(关联图谱)
- `Submission`：id, assignment_id, student_ref(哈希), answers(JSON), status, submitted_at
- `GradingItem`：id, submission_id, question_id, auto_score, ai_suggest_score, ai_confidence, ai_comment, final_score, final_comment, status
- `MistakeFeedback`：id, knowledge_point_id, pattern_text, error_rate, source(教学回流), status(待确认/已采纳/已驳回)

### 5.2 复用现有
- 知识图谱`知识点.误区+纠正`：FR-08 回流写入目标字段
- `lesson_plan_graph` 产出的`课堂习题`：FR-01 数据源
- 现有 LLM 流水线（多模型降级）：FR-04/FR-05 复用

### 5.3 埋点需求
| 事件 | 触发时机 | 上报字段 |
|------|----------|----------|
| assignment_published | 作业发布 | assignment_id, question_count, kp_count |
| grading_confirmed | 教师终评确认 | submission_id, ai_confidence, adopted(bool) |
| mistake_feedback_decided | 误区建议处理 | kp_id, decision(采纳/驳回) |

## 六、非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 单份 Submission AI 批改（≤20 题）端到端 ≤ 8s（P95，估算）；看板加载 ≤ 1s |
| 安全 | 学生身份去标识化存储；教师越权访问拒绝；导出文件不含明文 PII |
| 兼容 | 复用现有 Vue3 前端与 FastAPI 后端，不新增技术栈 |
| 可访问性 | 复核页关键操作（采纳/改分/确认）支持键盘可达与明确反馈 |

## 七、异常处理清单

| 场景 | 表现 | 处理方式 |
|------|------|----------|
| AI 主观题超时/失败 | 某题无建议 | 标记"AI 不可用，转人工"，不阻塞其余题目 |
| 置信度过低 | confidence < 0.7 | 强制"建议人工"，终评必须教师手填 |
| 标准答案缺失 | 客观题无 std_answer | 提交时拦截，提示教师补标准答案 |
| 学生重复提交 | 同一 student_ref 多次提交 | 以最后一次为准，旧版本标记"被覆盖" |
| 图谱知识点被删 | 作业关联的知识点已删除 | 看板该知识点标"已失效"，错误率单列不计入活跃统计 |

## 八、合规与数据保护（未成年人数据红线）

- **去标识化**：`student_ref` 一律存学号哈希或昵称，禁止明文姓名/身份证。
- **最小必要**：仅采集答案文本与得分，不采集阅读速度、停留时长、兴趣偏好等行为画像。
- **存储与删除**：作业与 Submission 设保留期（默认学期结束+30 天），到期提供批量删除；删除不可恢复。
- **不商业化**：批改数据不得用于广告推送或第三方共享。
- **教师主体责任**：AI 仅辅助，终评由教师确认，规避"算法替代育人"的合规与伦理风险。
- 若未来上线真实学生端，须前置：监护人单独同意 + 教育局/学校授权备案，不在本期范围。

## 附录：用户故事

**US-01（任课教师 · 提效）**
作为任课教师，我想要从教案一键生成作业并由 AI 辅助批改，以便把主观题复核耗时降一半以上。
- Given 教案已生成，When 一键生成作业并发布，Then 客观题自动判分、主观题给出建议分与评语。
- Given AI 给出建议，When 教师采纳或改分并确认，Then 终评落库且不可逆。

**US-02（教研管理员 · 质量闸门）**
作为教研管理员，我想要看全校知识点错误基线，以便识别需强化的教学盲区。
- Given 多班作业完成，When 打开校本看板，Then 按知识点展示错误率 TOP 与高频误区。

**US-03（图谱反哺 · 飞轮）**
作为任课教师，我想要把高频错误一键补入知识图谱误区节点，以便下次备课自动规避。
- Given 某知识点错误率≥40%，When 教师确认回流建议，Then 该知识点误区新增一条"教学回流"来源记录。
