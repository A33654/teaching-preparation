## 一、项目概述

**一句话定位**：基于知识图谱 + LangGraph 智能体的教师智能备课系统——教师只需选择章节，系统自动联动知识体系生成教案；管理员通过审核队列维护全局知识图谱，形成「使用-补全」闭环。

**双角色架构**：

| 角色 | 职责 | 界面 |
|---|---|---|
| 教师 | 备课（选章节→自动生成教案→编辑导出） | 教师端 8 页 |
| 管理员 | 知识库维护（审核候选知识点→写入图谱） | 管理端 4 页 |

## 三、后端技术

### 3.1 FastAPI（Python Web 框架）

- **是什么**：高性能异步 Python Web 框架，自动生成 OpenAPI 文档。
- **怎么用**：全部 API 用 `APIRouter` 组织（`app/api/routes/` 下 11 个路由模块），依赖注入（`Depends`）处理鉴权与会话。
- **用在哪**：所有 HTTP 接口（登录、文档上传、教案生成、知识图谱 CRUD、审核队列、SSE 聊天流）。

### 3.2 SQLModel + PostgreSQL（业务数据库）

- **是什么**：SQLModel = Pydantic + SQLAlchemy 的融合 ORM；PostgreSQL 18 存业务数据。
- **怎么用**：模型定义在 `app/models.py`；数据库迁移用 Alembic（`alembic upgrade head`）；查询用 SQLModel 的 `select` 语句；`pool_pre_ping=True` 处理数据库重启后的连接自愈。
- **用在哪**：用户表、文档表（含 `knowledge_point_ids` JSON 列引用 Neo4j 节点）、教案表、PPT 记录表、**候选知识点表**（审核队列）、**系统日志表**。

### 3.3 JWT 认证 + 角色隔离

- **是什么**：JSON Web Token 无状态认证。
- **怎么用**：登录返回 access_token；前端存 localStorage，axios 拦截器统一附 `Authorization: Bearer`；`deps.py` 解码校验；认证失败一律 401（前端自动清 token 跳登录），业务权限不足才 403。
- **用在哪**：所有接口鉴权 + 教师/管理员角色分流（`is_superuser` 字段）。

### 3.4 工具函数与工具描述（Agent 工具设计）

- **工具函数**：`app/agent/tools/knowledge_graph_tools.py` 封装 3 个 `@tool`：
  - `search_knowledge_graph`（分词打分检索：名称命中权重 3 > 描述命中 1）
  - `get_knowledge_point_detail`（详情+直接关系）
  - `get_knowledge_neighbors`（沿关系遍历邻居）
- **工具描述文档**：每个 docstring 含【调用时机】【输入】【输出】+ 系统提示的禁止场景（寒暄不调用、无结果不编造），这是 LLM 决策的唯一依据。
- **异常捕获**：工具内 try/except，数据库异常返回结构化 JSON 错误（不泄露 traceback 给模型）。

## 四、知识图谱技术

### 4.1 Neo4j 5.26（图数据库）

- **是什么**：原生图数据库，节点+关系模型。
- **怎么用**：全部查询走**纯 Cypher**（无 APOC 依赖）；`app/knowledge_graph/repository.py` 是图谱唯一读写入口；驱动单例（`max_connection_lifetime=1800` 连接自愈）；启动时幂等创建约束索引（节点 id 唯一约束 + 名称索引）。
- **用在哪**：知识点、考点、误区三类节点 + 文档/教案关联节点。

### 4.2 图谱 Schema

**节点**：

| 标签 | 属性 | 说明 |
|---|---|---|
| KnowledgePoint | name/subject/description/grade_level/difficulty/is_key_point | 知识点 |
| ExamPoint | name/level(了解/理解/掌握)/description | 考点（考纲要求） |
| Misconception | content/correction | 误区/易错点 |

**关系**：

| 关系 | 语义 | 特殊机制 |
|---|---|---|
| PREREQUISITE | 前置依赖（学习顺序） | — |
| PREREQUISITE_FOR ⇄ DEPENDS_ON | 前置/反向 | **自动双向维护** |
| CONTAINS | 包含 | — |
| RELATED_TO | 相关 | — |
| PARALLEL | 平行并列 | 自动建反向边（无向语义） |
| HAS_EXAM_POINT | 知识点→考点 | 专用 link 方法 |
| HAS_MISCONCEPTION | 知识点→误区 | 专用 link 方法 |

**双向维护机制**：创建 `prerequisite_for` 时自动 MERGE 反向 `depends_on`——后续查询无需写复杂反向逻辑（论文可写的图建模技巧）。

**节点状态与质量保障**：
- 所有节点带 `status` 属性（pending_review / published）；候选数据在 PG 审核队列暂存，**审核通过写入 Neo4j 即 published**；Agent 所有备课查询强制过滤 `status='published'`，未审核数据不可见。
- 管理员图谱质量检测（`/admin/graph-quality`）：非法循环依赖（PREREQUISITE/CONTAINS 同型自环，合法双向边不误报）、孤立节点、核心知识点缺少前置——图谱质量保障点。

### 4.3 全局共享 + 全局去重

- 知识库是管理员维护的**全局共享图谱**：备课联动检索不过滤 owner。
- 审核写图、批量导入均按**名称全局去重**（`find_by_name(owner_id=None)`），杜绝同名节点重复。

## 五、AI 智能体技术

### 5.1 LangChain（LLM 接入层）

- **是什么**：大模型应用开发框架。
- **怎么用**：`ChatOpenAI` 统一接入三个 provider 的 OpenAI 兼容接口；结构化输出统一走 **function_calling 模式**（`with_structured_output(schema, method="function_calling")`）——实测 json_schema 模式被 DeepSeek 400 拒绝，json_object 要求 prompt 含 "json" 字样，function_calling 是三 provider 都支持的路径。
- **用在哪**：聊天、抽取、教案、概括、PPT 大纲的全部 LLM 调用。

### 5.2 多 Provider 三级降级

- **机制**：启动时对配置的 provider 逐一做 1-token 探测（httpx 试调），缓存可用项。
- **优先级**：Qwen（qwen-plus）→ DeepSeek（deepseek-chat）→ Kimi（kimi-k2.6），Key 失效自动降级。

### 5.3 LangGraph（智能体编排层）

- **是什么**：图结构的状态机编排框架。
- **怎么用**：`StateGraph` 定义节点与条件边；6 张图：
  - **chat 图**（混合决策）：规则层意图识别 → 强制预检索兜底（可开关）→ ReAct 工具循环（`ToolNode` + `tools_condition`，LLM 自主决定工具调用时机）
  - **extraction 图**：学科识别 → 逐块抽取 → 关系清洗 → 写入候选队列 → 概括
  - **lesson_plan 图（一键备课固定流水线）**：图谱子图查询 → RAG 教材素材检索 → LLM 生成初稿 → **知识点自检（规则校验：缺失知识点/未覆盖考纲/遗漏前置/教学顺序风险）** → 输出教案 + 结构化校验报告。业务按钮固定走此流水线（意图路由隔离：聊天框消息才进 ReAct chat 图，LLM 不参与路由决策）
  - **summarize 图 / PPT 大纲图**：文档概括、PPT 大纲
- **流式输出**（关键实现）：prebuilt `create_react_agent` 内部用非流式 `invoke`，SSE 拿不到 token。最终方案：**agent/tools 节点平铺进顶层图**（子图流式不冒泡）+ 节点内显式 `model.stream(messages, config)`（config 必须注解 `RunnableConfig` 才会被注入）+ `stream_mode=["messages","values"]` 双流（messages 流自动出 token 与工具结果，values 兜底提取完整回复）。

### 5.4 SSE 流式事件协议

前后端统一事件格式：

| 事件 | 含义 |
|---|---|
| `token` | 大模型逐字输出 |
| `tool_result` | 工具调用完成（含 `forced` 标记区分自主/兜底、来源引用） |
| `done` | 完成（完整回复 + 汇总来源） |
| `error` | 出错 |

### 5.5 长文档抽取流水线

- **分块**：标题切分优先（中英文标题正则）→ 段落聚合回退 → 超长块按句切分 + 100 字重叠（防跨块知识点被切断）。
- **逐块抽取**：每块 ≤2500 字符（≈3000 token）+ 结构化输出；**上下文超限自动对半缩小重试**（2500→1250→800）。
- **容错**：每块失败打印完整真实错误日志（块号/标题/长度/repr(e)），回退正则提取器。
- **合并**：跨块同名知识点合并 + 关系引用完整性校验 + 类型白名单 + 去重。

### 5.6 RAG 兜底策略

- 章节检索图谱：命中 ≥3 个知识点 →「知识库完整，图谱驱动生成」；<3 →「部分缺失」；0 →「缺失，RAG 兜底」。
- 兜底时 requirements 注入「基于教材文本生成，不编造图谱依据」约束。

## 六、前端技术

### 6.1 Vue 3 + TypeScript + Vite

- 组合式 API（`<script setup>`）；Vite 7 开发服务器（5173 端口，`/api` 代理到后端 8000）。

### 6.2 Element Plus（UI 组件库）

- 全局注册（含图标库）；el-table/el-form/el-dialog/el-tree/el-upload/el-tabs 等贯穿全部页面。

### 6.3 状态与路由

- **Pinia**：auth store（用户信息、登录/登出/fetchMe）。
- **Vue Router**：路由守卫三重逻辑——未登录跳登录、管理员访问教师页踢回 `/admin`、教师访问管理页踢回工作台。

### 6.4 其他库

| 库 | 用途 |
|---|---|
| axios | HTTP 客户端；拦截器统一带 token、401 清 token 跳登录、非 401 弹错误 |
| `authorizedFetch` 封装 | SSE 聊天流、Word/PPT/文件下载等原生 fetch 场景统一 401 处理 |
| marked | 教案 Markdown 渲染 |
| el-tree | 章节知识脉络树状展示（层级=前置→后继学习顺序） |

## 7. 环境部署

| 组件 | 部署方式 | 启动命令 |
|---|---|---|
| PostgreSQL 18 | Windows 原生（EDB 官方 zip 解压） | `pg_ctl -D E:/work/pgsql/data start` |
| Neo4j 5.26 | WSL Ubuntu（官方 apt 仓库 deb 解包 + JDK 21 华为镜像） | `bash scripts/start-neo4j-wsl.sh` |
| 后端 | uv 管理依赖 | `cd backend && uv run fastapi run app/main.py --reload` |
| 前端 | npm | `cd frontend && npm run dev` |

> 完全脱离 Docker。后端直连 WSL 虚拟机 IP（Windows 的 WSL localhost 转发不可靠），启动脚本自动同步 IP 到 `.env`。

### 备选部署方案（降低演示环境故障风险）

> 本项目原型主要演示使用 WSL+Neo4j；为降低现场演示故障，提供两套备选。

| 方案 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| 方案一：PostgreSQL + Apache AGE | Windows 原生部署，图数据存 PG 扩展 | Cypher 语法高度兼容，无需 WSL，无 IP 转发问题 | AGE 成熟度一般，需 PG 扩展管理 |
| 方案二：PostgreSQL 邻接表 | 两张 SQL 表 `entity` / `relation` | 完全不需要图数据库扩展，SQL-CTE 递归实现依赖查询 | 深层递归性能弱，适合小规模教材图谱 |

另：生产级可使用 Docker-Compose 一键编排所有服务，避免 WSL 手工环境问题（毕设原型未采用）。

## 十、核心业务流程

### 流程 A：教师备课（图谱驱动 + RAG 兜底）

```
选学科/年级/教材/章节
  → 自动检索知识图谱（chapter-context 接口，后台 Cypher 聚合）
  → 右侧【本节备课参考】业务清单（重难点/前置链/误区/考纲/教学顺序，只读）
  → 完整度评分（核心知识点占比，非数量统计）
  → 一键生成：图谱命中 → 图谱驱动生成（含考纲层次+易错点辨析）
            图谱缺失 → 自动 RAG 兜底（不编造图谱依据）
  → 四步进度动画 → 教案编辑页（Markdown 渲染/校验/导出 Word）
```

### 流程 B：增量图谱补全闭环（论文核心创新）

```
教师上传 PDF / 管理员批量导入教材
  → 后台分块抽取（标题切分+重叠+上下文超限自动缩小重试）
  → 候选知识点进入待审核队列（不直接入图）
  → 管理员批量/单条审核：通过 → 全局去重写入 Neo4j；驳回；编辑修正
  → 正式知识图谱增长 → 下次备课自动感知（章节联动覆盖度提升）
```

### 流程 C：知识图谱自动校验教案

```
教案生成时：注入图谱的前置依赖/考点考纲/常见误区
  → Prompt 硬约束：覆盖考纲层次 + 设置易错点辨析
教案编辑时：前端比对教案文本与图谱知识点名 → 缺失高亮
  → 教师一键提交缺失知识点 → 进入审核队列 → 图谱补全
```

## 十一、关键设计决策

1. **章节驱动，无感赋能**：教师永不手动选知识点——图谱提供结构化教学知识骨架，AI 提供生成与交互，彻底解耦。
2. **全局共享图谱 + 人工审核**：LLM 抽取结果必须过审核队列才入图，保证图谱质量；全局按名去重保证唯一性。
3. **混合决策架构（chat）**：规则层强制预检索兜底（防模型跳工具空答）+ LLM 自主决策（灵活性）双保险。
4. **三流合一 SSE**：messages 流（工具+token）+ values 流（回复兜底）；agent 节点平铺顶层图是流式生效的前提。
5. **function_calling 结构化输出**：实测规避了 DeepSeek json_schema 400 与 json_object 的 prompt 限制。
6. **双向关系维护**：prerequisite_for ⇄ depends_on 成对写入，反向查询零成本。
7. **实体克制**：考点/误区入图（支撑教案校验），例题/习题留在 RAG 文本检索——避免图谱膨胀。
8. **失败可观测**：抽取逐块日志（块号+真实错误）、系统任务日志页、文档失败状态——「长 PDF 抽取失败」可定位可排查。

## 十二、答辩要点提示

**演示路径（建议 8 分钟）**：

1. 教师登录 → 新建备课 → 填「勾股定理」→ 右侧自动出现知识脉络树（点节点看考点/误区释义）→ 一键生成 → 教案编辑（校验/导出）
2. 教师上传补充 PDF → 提示「已进入审核队列」
3. 切换管理员 → 统计看板（待审核 +N）→ 审核队列**全选批量通过** → 知识库管理看图谱可视化新节点 → 系统日志看全链路记录
4. 回到教师端 → 重新查同一章节 → 完整度从「缺失」变「完整」（闭环证据！）

**一句话总结**：

> 知识图谱提供结构化教学知识骨架与逻辑约束，AI 助手提供自然语言生成与交互能力；教师无需操作知识图谱，仅需选择备课章节——图谱命中走图谱驱动，缺失自动 RAG 兜底，并通过「抽取→审核→入图」的增量补全闭环持续进化。
