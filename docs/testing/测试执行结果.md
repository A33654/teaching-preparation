**重要发现（已修复测试、非产品缺陷）**：`verify_password` 的真实契约是
`tuple[bool, str | None]`（pwdlib `verify_and_update` 的返回值），不是裸 `bool`。
原测试写成 `assert verify_password(...) is True`，实际得到 `(True, None)`，导致 5 个用例失败。
逐一核对 `crud.py:52`、`users.py:110`、`login.py:159` 三处调用方，**应用侧均正确解包** `verified, _`，
不存在「恒为已认证」的安全漏洞；本次修正的是测试代码，并在测试 docstring 中固化了该契约说明。

## 三、缺陷清单（5 项，均 P2，已以 xfail 固化）

| # | 模块 / 接口 | 现象 | 期望 | 影响 |
|---|---|---|---|---|
| 1 | `ScheduleCreate.subject` | 空串被接受 | 422 | 产生无意义的空科目日程 |
| 2 | `TaskCreate.title` | 空串被接受 | 422 | 产生无标题任务，列表难以辨识 |
| 3 | `SubjectCreate.name` | 空串被接受（字段 unique 但不禁止空串） | 422 | 空名学科，且占用唯一键会阻断第二次创建 |
| 4 | `TextbookCreate.subject_id` | 非 UUID 字符串通过 pydantic 后，在 `uuid.UUID()` 抛未捕获 `ValueError` → **500** | 400/422 | 未捕获异常暴露 500，掩盖了本应是参数校验错误的语义 |
| 5 | `admin.reject_suggestion` | 对**已审核通过**的工单再次驳回仍返回 200 | 400 | 与 `approve_suggestion` 的「已处理」守卫不对称，可能把已通过的建议改回驳回状态 |

**修复建议**：1–3 在 Pydantic schema 上补 `min_length=1`；4 把 `subject_id` 改为 `UUID` 类型或加 `field_validator` 显式捕获；5 复用 `approve_suggestion` 中的状态守卫逻辑。

### 过程中修复的产品缺陷（3 类共 6 处，均阻塞启动/运行时）

这几项在搭建测试环境时暴露，已直接修复源码，否则服务根本无法启动：

1. `app/models.py` — `LessonPlan.owner_id` 缩进错误（4 空格误写），导致 `IndentationError`，**应用无法导入**。已改为 6 空格。
2. `app/models.py` — `UserRole` 定义晚于 `Role`，SQLModel 在类定义期检查 `link_model` 触发前向引用 `NameError`。已将 `UserRole` 前置。
3. `app/api/routes/lesson_plans.py` — 4 处 `Annotated[...] = Depends(rbac.require_permission(...))` 与默认值冲突，FastAPI 直接拒绝注册路由。已替换为作者预留的 `rbac.RequireReview` / `rbac.RequireKbManage` 别名。

## 四、测试资产与工程说明

### 目录结构

```
backend/tests/
├── conftest.py                 # 全局离线底座：SQLite(:memory:, StaticPool) + GUID 类型适配 + Neo4j/LLM Mock
├── unit/                       # L0 单元测试
├── api/l1/                     # L1 接口功能测试
│   ├── conftest.py             # 路由模块级 patch（Neo4j / LLM）+ 组织租户种子
│   ├── fakes.py                # 内存版 KnowledgeGraphRepository + LLM 假实现
│   ├── helpers.py              # 基于 API 的数据构造器（名称带随机后缀，规避唯一键冲突）
│   └── test_*.py               # 11 个模块用例
├── ai_eval/                    # L3 AI 评测
│   ├── rubric.py               # 6 维加权评分卡
│   ├── test_ai_eval.py         # 跑 3 类 AI 产出并落盘 results/ai_eval.json
│   └── results/ai_eval.json
├── jmeter/                     # L2 性能/压力脚本（8 套 .jmx + build_jmx.py + users.csv）
└── platform/                   # 测试自动化平台
    ├── runner.py               # 编排：单元 → 接口 → AI 评测 → JMeter（可选）
    ├── config.py / config.yaml # 阈值与环境变量
    ├── report/generator.py     # HTML 报告生成
    └── results/                # results.json + junit-*.xml + report.html
```

### 关键工程决策

1. **离线可跑**：沙箱无 PostgreSQL / Neo4j / LLM Key，因此 `conftest.py` 把数据库换成内存 SQLite，
   用 `GUID` TypeDecorator 适配 `Uuid` 列，并对 Neo4j 驱动与 LLM 工厂注入假实现。
   这样 L0 / L1 / L3 在无任何外部依赖下 100% 可重复执行（约 13 秒）。
2. **Mock 必须打到「路由模块」而非「源模块」**（本次最重要的踩坑）：
   路由文件在导入时执行 `from app.knowledge_graph import KnowledgeGraphRepository`，
   把名字绑定进**自己的命名空间**。只 patch `app.knowledge_graph` 无效，
   必须用 `ExitStack` 逐个 patch `admin / chat / curriculum / documents / knowledge_points / lesson_plans` 六个路由模块。
   LLM 同理（`lp_rt.run_lesson_plan`、`docs_rt.run_extraction`、`chat_rt.astream_chat_events` 等）。
3. **唯一键冲突**：内存 DB 为 session 级共享、跨用例累积，而 `Subject.name` 有 UNIQUE 约束。
   数据构造器统一追加 `uuid4().hex[:8]` 随机后缀，避免「单跑通过、全量失败」。
4. **环境限制项**：文档删除用例中真实的 `Path.unlink()` 被沙箱安全策略拦截
   （`SAFE_DELETE_FAIL_CLOSED`），属环境限制而非应用缺陷，已在该用例中把 `unlink` 置为空操作以验证 DB 记录删除逻辑。
