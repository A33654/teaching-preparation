# 教师智能备课系统 · 测试执行计划

> 项目：教师智能备课系统（知识图谱 + LangGraph 智能备课平台）
> 技术栈：FastAPI + SQLModel + PostgreSQL 18 + Neo4j 5.26 + LangGraph + Vue3/TS
> 版本：v1（毕设演示版） · 计划生成日期：2026-10-26
> 范围：功能测试（正常/空白值/错误/边界）→ 性能与压力测试（JMeter）→ AI 评测测试 → 自动化测试平台搭建

---

## 1. 计划概述

### 1.1 测试目标
对系统建立从**单接口到全链路、从功能正确到非功能健壮、从传统断言到 AI 质量评测**的四层测试体系，并搭建一套可重复执行、可量化、可可视化的**测试自动化平台**。

### 1.2 被测系统接口全景
接口前缀统一为 `/api/v1`，共 **14 个路由模块、约 100 个端点**：

| 模块 | 前缀 | 关键端点（代表性） | 鉴权 |
|---|---|---|---|
| 登录 | `/login` | `POST /login/access-token`、`POST /password-recovery/{email}`、`POST /reset-password/` | 公开/邮箱 |
| 用户 | `/users` | 注册/查询/改密/删除（超管） | JWT + 超管 |
| 工具 | `/utils` | `POST /utils/test-email`、`GET /utils/health-check/` | 混合 |
| 物品(模板) | `/items` | CRUD | JWT |
| 知识点 | `/knowledge-points` | 图谱/CRUD/关系/子图/检索/章节上下文/考点/误区 | JWT |
| 备课 | `/lesson-plans` | 列表/生成/AI生成/提交/审批/发布KB | JWT + 角色 |
| 文档 | `/documents` | 上传/解析/分析/检索 | JWT |
| 对话 | `/chat` | `POST /chat/`（SSE 流式） | JWT |
| 课程 | `/curriculum` | 学科/教材/章节/看板 | JWT |
| 提醒 | `/reminders` | 日程/任务/今日概览 | JWT |
| 摘要/PPT | `/summarize` | 摘要/生成PPT/列表/导出 | JWT |
| 管理 | `/admin` | 统计/候选队列/批量审批/图谱质量/日志/建议 | 超管 |
| 私有(仅local) | `/private` | 造数接口 | 无（local） |

> 鉴权实现：`get_current_user`(JWT) + `get_current_active_superuser`。README 明确声明 **401/403 语义分离**，是重点验证项。

### 1.3 测试类型与分层
| 层级 | 测试类型 | 主要工具 | 是否依赖外部服务 |
|---|---|---|---|
| L0 | 单元/纯逻辑 | pytest（无 DB/LLM） | 否 |
| L1 | 接口功能（正常/空白/错误/边界） | pytest + TestClient | Postgres（测试库） |
| L2 | 性能/压力 | JMeter 5.6 + Java 17 | 完整栈 + Neo4j |
| L3 | AI 评测 | 自研 rubric 评分器 + 规则校验 | LLM Key（可 Mock 降级） |

## 2. 测试环境与前置条件

### 2.1 环境分层（Tier）
| Tier | 能力 | 当前沙箱是否可跑 | 缺口 |
|---|---|---|---|
| Tier-0 | L0 单元测试 + 计划冒烟 | ✅ 可跑 | 无 |
| Tier-1 | L1 接口测试 | ⚠️ 需 Postgres 18 测试库 | 本机无 PG，可用 Docker/TestContainers 或 SQLite 兼容层 |
| Tier-2 | L2 性能/压力 | ❌ 需 Java17 + JMeter + 完整栈 | 本机无 Java/PG/Neo4j |
| Tier-3 | L3 AI 评测 | ⚠️ 需 LLM Key；可先跑 Mock 降级 | 无 Key 时走 Mock |

### 2.2 依赖清单
- PostgreSQL 18（测试库，独立于生产，建议 `tty_test`，端口 15433）
- Neo4j 5.26（测试实例，端口 17474/17687）
- Java 17+、Apache JMeter 5.6（性能测试）
- Python 3.13 + pytest ≥ 7.4、httpx（TestClient 已含）
- LLM：Qwen/DeepSeek/Kimi 任一 Key（三级降级，缺失时 Mock）
- 可选：Docker Compose（一键起完整栈，端口偏移）

### 2.3 测试数据策略
1. **演示库（seed_demo）**：系统内置初中物理 34 节点知识库，幂等灌库，作为功能/图谱测试基线数据。
2. **Fixture 造数**：pytest fixture 创建隔离的 teacher/admin 账号、学科/教材/章节、知识点、备课记录。
3. **边界/异常数据**：空串、超长串（>max_length）、非法 UUID、不存在 ID、越权角色、超大上传文件、损坏的 PDF/DOCX。
4. **Mock 数据**：LLM 返回使用录制/桩响应，保证 AI 评测与流水线在离线环境可复现。

## 3. 测试自动化平台架构

### 3.1 总体设计
```
tests/
├── platform/                # 自研测试自动化平台
│   ├── config.py            # 环境/阈值/场景配置（YAML）
│   ├── runner.py            # 统一执行入口（CLI）：unit / api / jmeter / ai-eval
│   ├── report/              # HTML 报告仪表盘生成器
│   │   ├── generator.py
│   │   └── templates/       # 仪表盘模板（概览/趋势/详情）
│   ├── notifier.py          # 结果通知（可选 webhook）
│   └── ci.yml               # CI 集成（GitHub Actions / 定时）
├── unit/                    # L0：纯逻辑/校验/工具函数
├── api/                     # L1：接口功能测试（基于现有 tests/ 扩展）
│   ├── conftest.py          # DB/Neo4j/LLM Mock fixture
│   ├── test_login.py ...    # 按模块
├── jmeter/                  # L2：性能/压力
│   ├── *.jmx                # JMeter 脚本
│   ├── run.sh               # 命令行执行 + 结果聚合
│   └── results/             # jtl + 报告
└── ai_eval/                 # L3：AI 评测
    ├── rubric.py            # 评分 rubric + 自动打分
    ├── cases/               # 评测用例（章节/题干）
    └── scorer.py            # 质量评分 + 对照基线
```

### 3.2 核心组件
- **执行引擎**：`runner.py` 统一调度 pytest（功能）与 JMeter CLI（性能），汇总成统一结果模型。
- **Mock 策略**：`conftest.py` 用 `monkeypatch` 注入 LLM 桩、Neo4j 内存桩、邮件桩，使 L1 在无全栈时仍可跑通核心路径。
- **报告仪表盘**：每次运行生成 `report/index.html`，含：通过率、各模块用例数、延迟百分位图（perf）、AI 质量雷达图、失败明细、趋势对比（历史 JSON）。
- **CI / 调度**：`ci.yml` 在 push/PR 触发 L0+L1；性能与 AI 评测由定时任务（每周/发版前）触发。

### 3.3 关键设计原则
- **可重复**：种子数据 + 幂等灌库 + 测试后清理（沿用现有 `conftest` 的 delete 逻辑）。
- **配置化**：所有阈值（延迟、吞吐、错误率、质量分）集中在 `config.py`，便于调参。
- **离线优先**：LLM/Neo4j 缺失时自动降级到 Mock，保证平台"装好就能跑"。

## 5. 性能与压力测试（JMeter）

### 5.1 测试场景
| 场景 | 目的 | 并发 | 持续 | 关注 |
|---|---|---|---|---|
| 基准（Baseline） | 单用户延迟基线 | 1 | 各接口 20 次 | 平均/中位延迟 |
| 负载（Load） | 常规容量 | 50 | 10 min | P95 延迟、吞吐、错误率 |
| 压力（Stress） | 找拐点 | 逐步 50→200→500 | 每级 5 min | 拐点（错误率↑/延迟飙升） |
| 耐力（Endurance） | 稳定性/泄漏 | 100 | 1 h | 内存/连接不增长 |
| 失败注入（Chaos） | 降级验证 | 100 | 期间杀 Neo4j/LLM | 返回降级而非雪崩 |

### 5.2 JMeter 脚本清单（.jmx）
1. `01-auth-login.jmx` — 登录获取 token（CSV 账号池 + 正则提取 token）。
2. `02-kp-list-graph.jmx` — 知识点列表/全量图谱/子图（核心读路径）。
3. `03-lesson-plan-crud.jmx` — 备课 CRUD + 提交审批（写路径）。
4. `04-doc-upload.jmx` — 文档上传 + 分析（含大文件）。
5. `05-chat-sse.jmx` — 对话流式（SSE 采样）。
6. `06-admin-batch.jmx` — 管理端批量审批（重路径）。
7. `07-mixed-load.jmx` — 混合业务负载（按权重配比）。
8. `08-stress-ramp.jmx` — 阶梯加压（Ultimate Thread Group / Stepping）。

> 公共元件：HTTP 请求默认值（host/port）、HTTP Header Manager（Authorization）、CSV Data Set（账号/章节 ID）、View Results Tree（调试）、Aggregate Report、Summary Report、jp@gc 监听器（响应时间百分位图、TPS、Active Threads）。

### 5.3 监控指标
- 响应时间：平均、P90、P95、P99、最大
- 吞吐：Requests/sec (TPS)
- 错误率：% of failures
- 资源：CPU/内存（后端）、PG 连接数、Neo4j bolt 连接、GC 次数
- 网络：带宽

### 5.4 合格指标（性能）
| 接口类别 | 并发 | P95 延迟 | 错误率 | 吞吐 |
|---|---|---|---|---|
| 读（health/list/图谱） | 50 | ≤ 200 ms | ≤ 0.1% | ≥ 200 TPS |
| 写（CRUD/提交） | 50 | ≤ 500 ms | ≤ 0.5% | ≥ 50 TPS |
| AI 生成（LLM 绑定） | 20 | ≤ 30 s | ≤ 1% | ≥ 2 TPS |
| 拐点 | — | 错误率 < 5% 且 P95 < 2×基线时的最大并发 | — | — |
| 耐力 1h | 100 | 无退化（延迟漂移 < 10%） | 0 泄漏 | 稳定 |

## 6. AI 评测测试

### 6.1 评测对象
备课初稿生成、教材摘要、PPT 生成、知识点抽取（抽取图）、ReAct 对话、规则自检报告（缺失知识点/未覆盖考纲/遗漏前置/顺序风险）。

### 6.2 评测方法（三合一）
1. **Rubric 自动打分**（0–5）：① 完整性（覆盖章节知识点）② 考纲覆盖 ③ 前置依赖正确 ④ 重难点突出 ⑤ 结构规范 ⑥ 无事实性硬伤。
2. **规则校验**：断言自检报告字段齐全、与图谱数据一致（前置链不出现断点、误区与节点匹配）。
3. **降级一致性**：三级 Provider 降级（Qwen→DeepSeek→Kimi）产出差异在 rubric 阈值内；全失败返回结构化错误。

### 6.3 评测数据集
- 正例：演示库章节（光的反射、透镜、凸透镜成像规律）各 3 套命题。
- 对抗：超长章节、空章节、跨章节、非物理学科（泛化）。
- 基线：人工/历史优质教案作为对照。

### 6.4 合格指标（AI）
| 维度 | 指标 | 合格线 |
|---|---|---|
| 质量 | rubric 平均总分 | ≥ 4.0 / 5.0 |
| 完整性 | 章节知识点覆盖率 | ≥ 90% |
| 考纲 | 考纲覆盖命中 | ≥ 85% |
| 前置 | 前置链断点 | 0 |
| 流式 | SSE 事件完整（token→done/error） | 100% |
| 降级 | 单 Provider 失败自动切换 | 成功切换 |
| 自检 | 报告字段齐全且一致 | 100% |

## 9. 风险与应对
| 风险 | 影响 | 应对 |
|---|---|---|
